## Per-task checklist

- [x] **4.1 Finance permission keys:** Verify each `finance.*` permission appears in role management and only intended operations are exposed.
- [x] **4.2 Finance access helper:** Verify superadmin bypasses permission checks, while an admin role without finance permission receives no access.
- [x] **4.3 Admin seed:** Create a fresh/default admin role/account; verify finance permissions are present and then revocable.
- [x] **4.4 Sidebar/routing:** Verify permitted user visibility, navigation, refresh/deep-link behavior, and denial for a revoked role across every routing map.
- [x] **4.5 Remove mock UI:** Build the application; grep confirms removed mock constants/screens are absent and real HR payroll remains reachable.
- [x] **4.6 P&L:** Seed known recognised revenue, COGS, commission, expenses, depreciation, and loan interest; hand-check monthly total and branch filter.
- [x] **4.7 Service margin:** Verify contribution margin uses snapshots, clearly flags/handles null costs, and matches a hand computation.
- [x] **4.8 Doctor/branch P&L:** Verify provider and branch grouping includes the right rows and excludes unlinked rows transparently.
- [x] **4.9 Cash flow:** Verify cash collected is distinct from recognised revenue; hand-check payments, purchases, expenses, and loan cash outflows.
- [x] **4.10 Receivables aging:** Seed unpaid invoices at each bucket boundary; verify bucket totals and invoice-age basis.
- [x] **4.11 Budget vs actual:** Configure budgets above/below actual expense and verify variance direction, branch scope, and period scope.
- [x] **4.12 Charts:** Confirm each chart renders a live API response, handles empty/error states, and has readable labels/tooltips.
- [x] **4.13 Finance UI:** Click every page as a permitted user and as a denied user; confirm no placeholder values or swallowed errors.
- [x] **4.14 Contract rollup:** Verify route responses and permission requirements match `API_CONTRACT.md` and evidence is recorded.
- [x] **4.15 Reporting UI:** Start the dev server, log in as a permitted role, click through every screen this task adds, confirm real dev data renders correctly and the 4.4 permission gate still holds for a revoked role.
